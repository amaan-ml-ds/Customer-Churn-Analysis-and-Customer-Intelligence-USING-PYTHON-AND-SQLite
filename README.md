# Customer Churn Analysis and Customer Intelligence

## Overview

This project explores customer churn using Python, Pandas, NumPy,
SQLite, Matplotlib, and Seaborn. It combines customer profile,
subscription, and customer-support data to create an analysis-ready
dataset, calculate churn and retention metrics, and visualize patterns
across plans, locations, and customer-risk categories.

The analysis is implemented in `churn_analysis.ipynb`, with source data
stored in `customer_churn.db`.

## Objectives

-   Load customer data from a SQLite database into Pandas DataFrames.
-   Clean and standardize customer, subscription, and support fields.
-   Build a customer-level dataset by joining the source tables.
-   Define a churn flag from cancellation dates.
-   Calculate core churn, retention, revenue, tenure, and support
    metrics.
-   Visualize churn patterns and explore relationships between selected
    variables.
-   Export the merged dataset for further analysis.

## Data Sources

The SQLite database contains three tables:

### `db_customer`

Customer profile information, including customer ID, name, country,
state, gender, date of birth, interests, and pincode.

### `db_subscription`

Subscription information, including subscription start and renewal
dates, subscription type, plan and contract types, cancellation date and
reason, monthly charges, customer lifetime value (`cltv`), and churn
score.

### `db_support`

Customer-support information, including complaint date, escalation
indicator, customer satisfaction score (`csat_score`), and additional
source fields.

The database supplied with this project contains 21 rows in
`db_customer`, 21 rows in `db_subscription`, and 9 rows in `db_support`.

## Workflow

### 1. Connect to SQLite and import the tables

The notebook connects to `customer_churn.db`, retrieves table names from
SQLite's `sqlite_master`, and loads each table into a Pandas DataFrame.
It also uses `PRAGMA table_info` to inspect table columns.

The notebook includes an optional setup cell to create a SQLite database
from `customer_churn_data_raw.xlsx`. This step is only needed if you are
rebuilding the database from that Excel file; the Excel file is not
included in the supplied project files.

### 2. Clean and standardize the data

The notebook performs the following transformations:

-   Renames the customer `name` column to `customer_name`.
-   Removes `interests` and `pincode` from the customer DataFrame.
-   Converts `dob` to a datetime value.
-   Standardizes gender values by replacing `Men` with `Male` and
    `Women` with `Female`.
-   Fills missing customer-country values using a state-to-country
    mapping derived from rows where country is present.
-   Converts subscription start, renewal, and cancellation dates to
    datetime values.
-   Removes `col_1` and `comment` from the support DataFrame.
-   Converts `complaint_date` to datetime.

### 3. Engineer features and combine tables

A binary `churn_flag` is created from the subscription cancellation
date:

-   `1` --- a cancellation date is present.
-   `0` --- a cancellation date is absent.

Before merging, support records are grouped by `customerid` to calculate
`complaint_count`. The support data is sorted by complaint date and
reduced to the latest record per customer. The subscription table is
then left-joined with the customer and support tables on `customerid`.

The merged dataset is exported as `exported_churn_data.csv` without a
Pandas index.

### 4. Calculate key metrics

The notebook calculates these measures:

  -----------------------------------------------------------------------
  Metric                              Method used in the notebook
  ----------------------------------- -----------------------------------
  Churn rate                          Mean of `churn_flag` multiplied by
                                      100

  Retention rate                      100 minus churn rate

  Churn by plan                       Mean of `churn_flag` grouped by
                                      `plan_type`, multiplied by 100

  ARPU                                Mean of `monthly_charges`

  Average tenure                      Mean number of days between
                                      subscription start and cancellation
                                      date, or between subscription start
                                      and the current date for customers
                                      without a cancellation date

  Revenue at risk                     Sum of `monthly_charges` for
                                      records where `churn_flag` equals 1

  Escalation rate                     Percentage of records where
                                      `escalations` equals `Y`

  Average complaints per user         Sum of `complaint_count` divided by
                                      the number of unique customer IDs

  Escalation--churn correlation       Correlation between the encoded
                                      escalation indicator and
                                      `churn_flag`

  Churn risk category                 `low` for churn scores below 50,
                                      `med` for scores from 50 to below
                                      70, and `high` for scores of 70 or
                                      above
  -----------------------------------------------------------------------

The notebook also contains a comment identifying churn analysis by state
and subscription type as additional work, and a comment identifying
customer-age calculation as homework; these are not implemented as
completed metric calculations in the supplied notebook.

**Metric interpretation note:** `revenue_at_risk` sums monthly charges
for churned records; it is not a calculation of total future revenue
loss. Likewise, the churn flag is based on the presence of a
cancellation date, as implemented in the notebook.

### 5. Visualize and explore the data

The notebook includes:

-   A monthly churn trend line chart based on cancellation month.
-   A churn-rate-by-plan bar chart.
-   A state-level churn bar chart (the chart title says "Churn by
    Country," while the data is grouped by state).
-   Correlation heatmaps using Seaborn and Matplotlib.
-   A pair plot of selected encoded variables.
-   A categorical comparison of monthly charges by plan type and gender,
    split by churn-risk category.
-   Pivot tables summarizing churn rate and aggregating monthly charges,
    unique customers, and churn rate by plan.

Categorical variables are encoded for correlation exploration. The
notebook first demonstrates category-code encoding and then defines an
explicit order for plan type, contract type, and churn-risk categories.

## SQL Used

The notebook uses SQL through SQLite for tasks such as:

-   Reading table data with `SELECT * FROM ...`.
-   Demonstrating table creation and inserts in a separate

## Setup and Usage

### Requirements

Install the Python packages used by the notebook:

``` bash
pip install pandas numpy matplotlib seaborn jupyter
```

SQLite support is provided by Python's built-in `sqlite3` module, so a
separate Python package is not normally required.

### Run the notebook

1.  Place `churn_analysis.ipynb` and `customer_churn.db` in the same
    working directory.
2.  Start Jupyter Notebook or JupyterLab.
3.  Open `churn_analysis.ipynb`.
4.  Run the cells from top to bottom so the database connection,
    DataFrames, transformations, and visualizations are created in
    order.
5.  The notebook writes `exported_churn_data.csv` to the current working
    directory.

If the database file needs to be rebuilt from Excel, provide
`customer_churn_data_raw.xlsx` and run the optional database-creation
cell. Otherwise, skip that cell and use the supplied database.

## Output

The main output is `exported_churn_data.csv`, which contains the merged
and transformed customer dataset, including engineered fields such as
`churn_flag` and `complaint_count`. Additional derived columns include
`tenure_days` and `churn_risk` within the notebook's analysis flow. The
notebook also displays summary metrics, charts, and pivot tables.

## Limitations and Notes

-   The notebook uses the current date when calculating tenure for
    customers without a cancellation date, so those values can change
    between runs.
-   Support data is reduced to the latest complaint record per customer
    after `complaint_count` is calculated. Consequently, support
    attributes in the merged dataset represent the latest retained
    support record, while `complaint_count` represents the number of
    source support records counted for that customer.
-   Validate row counts after joins to ensure the merged dataset has the
    intended grain and does not duplicate customers.
-   The notebook's chart labels and some variable names contain minor
    inconsistencies; for example, the state-level chart is titled as if
    it were grouped by country.
-   The notebook includes a separate SQL learning example using a
    `users` table. That example is instructional and is not part of the
    customer churn database workflow.
-   No predictive machine-learning model training or deployment is
    implemented in this notebook; the supplied work is exploratory
    analysis and visualization.
